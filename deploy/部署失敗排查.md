# 部署失敗排查（Railway / Vercel / 本機 Docker）

> 本專案已不依賴 **GCP Cloud Run、Cloud SQL、Cloud Run Jobs**。若文件他處仍出現 `gcloud run` 或 Cloud SQL 步驟，請視為過時敘述。

## 後端（Railway 等）

| 現象 | 可能原因 | 建議 |
|------|----------|------|
| Healthcheck `/health` 失敗 | 程序未聽 `PORT`、或 `start.py` 路徑錯誤 | 確認 Dockerfile CMD、勿覆寫為錯誤的 `startCommand` |
| 啟動後立刻崩潰 | `DATABASE_URL`、Redis、或 Alembic 連線失敗 | 看 Deploy Logs；本機用 `docker compose logs backend` |
| 影片永遠排隊 | 無 Celery worker 或 `queue_video` 未消費 | 另起 worker 服務並設定與 API 相同 broker |

## 前端（Vercel 等）

| 現象 | 可能原因 | 建議 |
|------|----------|------|
| 建置失敗 | 缺環境變數 | 設定 `NEXT_PUBLIC_API_URL`、`NEXT_PUBLIC_SITE_URL` |
| API 全 401/CORS | `NEXT_PUBLIC_API_URL` 與實際後端網域不一致 | 對齊正式 API 網址 |

## 本機

```bash
docker compose ps
docker compose logs -f backend
```
