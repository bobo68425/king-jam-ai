# King Jam AI — 部署線上（Vercel / Railway）

正式環境：**前端**（例：Vercel 或靜態／容器託管）、**後端與資料庫**（例：Railway 或其他雲），**不再使用** GCP Cloud Run、Cloud SQL、Cloud Run 網域對應或 Cloud Run Jobs。

## 方式一：推送程式碼觸發部署

1. 將變更推上 `main`（或你綁定的分支）。
2. **前端**：在 Vercel（或你的前端託管）查看 Build / Deploy 狀態。
3. **後端**：在 Railway（或你的 API 託管）查看 Deploy 日誌與 `/health`。

## 方式二：資料庫遷移（GitHub Actions）

若 schema 有變更：

1. 在 **GitHub → Settings → Secrets and variables → Actions**（或對應 Environment）新增 **`DATABASE_URL`**：須為可從 GitHub 連線之 Postgres（通常為託管商提供之連線字串，含 SSL 若需要）。
2. 可移除不再使用之舊 Secret：`GCP_PROJECT_ID`、`GCP_SA_KEY`、`DB_PASSWORD`（僅舊 Cloud SQL Proxy 流程會用到）。
3. **Actions** → **Database Migration** → **Run workflow** → 選環境與動作（例如 `upgrade`）。

遷移目標為你目前實際使用的 Postgres。

## 本機 Docker 遷移

```bash
cd deploy && chmod +x run-migrations.sh && ./run-migrations.sh
```

## 部署後檢查

- **API**：`https://api.kingjam.app/health`（或你的 API 網域）應回 `{"status":"ok",...}`。
- **前端**：`https://kingjam.app` 可正常開啟。

## 網域（DNS）

- `kingjam.app` / `www`：依前端託管（例如 Vercel）指示設定 CNAME。
- `api.kingjam.app`：指向**目前 API 主機**（例如 Railway 提供的目標），**勿**再使用 `ghs.googlehosted.com`（舊 Cloud Run 對應）。
